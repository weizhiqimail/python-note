## 1. IO编程
+ IO在计算机中指input和output，也就是输入和输出。由于程序和运行时数据时在内存中，由CPU来执行，涉及到数据交换的地方，通常是磁盘，网络等。
+ 同步和异步的区别就在于是否等待IO执行的结果。
+ 使用异步IO来编写程序性能会远远高于同步IO，但是异步IO的缺点是编程模型复杂。
+ 操作IO的能力都是由操作系统系统的，每一种编程序猿都会把操作系统提供的低级C接口封存起来方便使用。

## 2. 文件读写
+ 读写文件前，在磁盘读写文件的功能都是由操作系统提供的，现在操作系统不允许普通程序直接操作磁盘，所以，读写文件就是请求操作系统打开一个文件对象(文件描述符)，然后通过操作系统提供的接口从这个文件对象中读取数据(读文件)，或者是把数据写入这个文件对象(写文件)

#### 2.1 读文件
+ `open()`打开一个文件对象
+ `f = open('/users/mark/grade.txt', 'r')`
+ 标识符`r`表示读，这样就成功地打开了一个文件
+ 如果文件不存在，`open()`函数就会抛出一个`IOError`错误，并且给出错误代码和相信信息来说明这个文件不存在
+ 如果文件打开成功，调用`read()`方法可以一次读取文件的全部内容。Python把内容读到内存，用`str`对象表示
+ `f.read()`
+ 最后是通过调用`close()`方法来关闭文件，文件使用完毕后必须关闭，因为文件对象会占用操作系统的资源，并且操作系统同一时间打开的文件数量有限
+ `f.close()`
+ 由于文件读写时都有可能产生`IOError`，一旦出错，后边的`f.close()`就不会调用，所以为了无论是否出错都能正确关闭文件，我们可以使用`try...finally...`来实现

```python
try:
    f = open('./a.txt', 'r')
    print(f.read())
finally:
    if f:
        f.close()
```
+ 但是每次都这么写太麻烦，所以使用`with`语句自动调用`close()`方法

#### 1.2 with语句
+ 使用`with`语句更加简洁，而不用调用`f.close()`方法

```python
with open('./a.txt', 'r') as f:
    print(f.read())
```
#### 1.3 read(),readline(),readlines()
+ 调用`read()`会一次性读取文件的全部内容，如果文件大小为10g，那么内存就会爆掉。
+ `read(size)`，所以为了保险起见，可以反复调用`read(size)`方法，每次最多读取`size`个字节的内容。
+ 调用`readline()`可以每次读取一行的内容
+ 调用`readlines()`一次读取所有内容并按行返回`list`

```python
with open('./a.txt', 'r') as f:
    for line in f.readlines():
        print(line.strip())
```
+ 如果文件很小，`read()`一次性读取最方便，如果不能确定文件大小，返回调用`read(size)`比较保险，如果是配置文件，调用`readlines()`最方便

#### 1.4 file-like Object
+ 像`open()`函数返回的这种有个`read()`方法的对象，在Python中统称为file-like Object，除了file外，还可以是内存的字节流，网络流，自定义流等。file-like Object不需要从特定类继承，只要写个`read()`方法就行
+ `StringIO`就是在内存中创建的file-like Object，常用作临时缓冲

#### 1.5 二进制文件
+ 读取二进制文件，比如图片视频等，用`rb`模式打开文件即可
+ 输出结果是以16进制表示的字节

```python
with open('./01.jpg', 'rb') as f:
    print(f.read())
```

#### 1.6 字符编码
+ 要读取非UTF-8编码的文本文件，需要给`open()`函数传入`encoding`参数

```python
with open('./a.txt', 'r', encoding='gbk') as f:
    print(f.read())
```
+ 遇到有些编码不规范的文件，可能会遇到`UnicodeDecodeError`，因为在文件中可能加杂了一些非法编码的字符，遇到这种情况，`open()`函数还接收到一个`errors`参数，表示如果遇到编码错误后如何处理，最简单的方式就是直接忽略

```python
with open('./a.txt', 'r', encoding='gbk', errors='ignore') as f:
    print(f.read())
```

#### 1.7 写文件
+ 写文件和读文件是一样的，唯一区别是调用`open()`函数时，传入标识符`w`或者`wb`表示写文本文件或写二进制文件

```python
with open('./a.txt', 'w') as f:
    print(f.write('this is write message'))
```
+ 可以反复调用`write()`来写文件，但是一定要调用`f.close()`来关闭文件
+ 当写文件的时候，操作系统不会直接把数据写入磁盘，而是放到内存中缓存起来，空闲的时候再慢慢写。只有调用`close()`方法时，操作系统才保证把没有写入的数据全部写入磁盘，忘记调用`close()`的后果就是可能写了一部分到磁盘，剩下的丢失了，所以使用`with`语句更加保险
+ 在写入特定编码的文件文件，要给`open()`传入`encoding`参数，将字符串自动转为指定编码。
+ 在使用`w`模式写入文件时，如果文件已经存在，会直接覆盖，相当于删掉这个文件，再重新写入这个文件。如果要是添加到文件末尾，可以使用`a`模式追加写入。

```python
with open('./a.txt', 'a') as f:
    print(f.write('\nthis is write message'))
```

## 2. StringIO和BytesIO
+ 数据读写不一定是文件，也可以是在内存中读写

#### 2.1 StringIO
+ 要把`str`写入`StringIO`，需要先创建一个`StringIO`
+ `f.write('hello')`是向内存里写一个字符串
+ `f.getvalue()`是f从内存里获取这个值

```python
from io import StringIO

f = StringIO()

f.write('hello')
print(f.getvalue())
```
+ 可以像读取文件一样读取

```python
from io import StringIO

f = StringIO('Hello!\nHi!\nGoodbye')

while True:
    s = f.readline()
    if s == '':
        break
    print(s.strip())
```

#### 2.2 BytesIO
+ 操作二进制数据，需要使用`BytesIO`，`BytesIO`实现了在内存中读写`bytes`
+ 注意写入的不是str，而是经过UTF-8编码的`bytes`

```python
from io import BytesIO
f = BytesIO()
f.write('大爷'.encode('utf-8'))
print(f.getvalue())
```
+ 可以用一个`bytes`初始化`BytesIO`，像读取文件一样读取

```python
from io import BytesIO
f = BytesIO(b'\xe5\xa4\xa7\xe7\x88\xb7')
print(f.read())
```

## 3. 操作文件和目录
+ Python程序中内置的`os`模块可以直接调用操作系统提供的接口函数
+ `os.name`查看操作系统，如果是`posix`，则说明是`Linux`,`Unix`,`Mac OS X`，如果是`nt`，就是`Windows`操作系统
+ `os.uname()`获取详细的系统信息，在`Windows`操作系统上不提供

```python
import os
print(os.name)
print(os.uname())
```

#### 3.1 环境变量
+ 在操作系统中定义的环境变量，全部保存在`os.environ`变量中
+ 要获取某一个环境变量的值，可以调用`os.environ.get('key')`

```python
import os
print(os.environ)
print(os.environ.get('USER'))
```
#### 3.2 操作文件和目录
+ 操作文件和目录的函数一部分放在`os`模块中，一部分放在`os.path`模块中
+ `os.path.abspath('.')`查看当前目录的绝对路径
+ `os.path.join('/user/mark', 'file')`在某个目录下创建一个新目录，首先把完整路径表示出来
+ `os.mkdir('/user/mark/phone')`创建一个新目录
+ `os.rmdir('/user/mark/del')`删除一个目录
+ 注意两个目录合成一个时，不要直接拼接字符串。而要通过`os.path.join()`函数，这样可以正确处理不同操作系统的路径分隔符。
+ 如果要拆分路径，不要去拆分字符串，而要用`os.path.split()`函数，这样可以把一个路径拆分为两部分，后一部分总是最后级别的目录或文件名
+ `os.path.splitext()`可以直接获取到文件扩展名
+ 这些合并拆分路径的函数不一样要求目录和文件要真实存在，只对字符串进行操作。
+ 复制文件函数在`os`中不存在，因为复制文件并非由操作系统提供的系统调用。但是可以通过读写文件可以完成文件复制。
+ 使用`shutil`模块提供了`copyfile()`函数，可以把`shutil`模块看做`os`模块的补充
+ 列出当前目录下所有的目录`[x for x in os.listdir('.') if os.path.isdir(x)]`
+ 列出所有的`py`文件`[x for x in os.listdir('.') if os.path.isfile(x) and os.path.splitext(x)[1] == '.py']`

## 4. 序列化
+ 在程序运行过程中，所有的变量都是在内存中，比如定义一个dict
+ 可以随时修改变量，但是一旦程序结束，变量所占用的内存就会被操作系统全部回收。如果没有把修改后的内容存储到磁盘上，下次重新运行程序，变量就会被初始化
+ 把变量从内存中编程可存储或传输的过程称之为序列化，在Python中叫做pickling，在其他语言中被称之为serialization，marshalling，flattening都是一个意思
+ 序列化之后，既可以把序列化后的内容写入磁盘，或者通过网络传输到别的机器上。
+ 反过来，把变量内容从序列化的对象重新读到内存里称之为反序列化，即unpickling
+ python中提供了`pickle`模块来实现序列化

```python
import pickle

d = dict(name='mark', age=18)
print(pickle.dumps(d))
```
+ `pickle.dumps()`方法把任意对象序列化成一个`bytes`，然后可以把这个`bytes`写入文件。或者用另一个方法`pickle.dump()`直接把对象序列化后写入一个file-like Object

```python
import pickle
d = dict(name='mark', age=18)
f = open('./a.txt', 'wb')
pickle.dump(d, f)
f.close()
print(d)
```
+ 用`pickle,dump()`直接把对象序列化后写入file-like Object，查看`a.txt`文件，是一堆乱码，这些是Python保存的对象内部信息
+ 把对象从磁盘读取到内存中的时候，可以先把内容读取到一个`bytes`，然后利用`pickle.loads()`方法反序列化对象，也可以直接用`pickle.load()`方法从一个file-like Object中直接反序列化出对象。

```python
import pickle

#  对象序列化
d = dict(name='mark', age=18)
print(pickle.dumps(d))
# b'\x80\x03}q\x00(X\x04\x00\x00\x00nameq\x01X\x04\x00\x00\x00markq\x02X\x03\x00\x00\x00ageq\x03K\x12u.'

#  对象序列化并写入文件
f = open('./a.txt', 'wb')
d = pickle.dump(d, f)
f.close()
# a.txt
# �}q (X   nameqX   markqX   ageqKu.

# 把内容反序列化为对象
f = open('./a.txt', 'rb')
d = pickle.load(f)
f.close()
print(d)
# {'name': 'mark', 'age': 18}
```
+ 这个变量和原来的变量不再是同一个东西，他们只是内容相同

## 5. JSON

#### 5.1 格式转换
+ 如果要在不同的编程语言之间传递对象，就必须把对象序列化为标准格式JSON。

JSON | Python
---|---
{} | dict
[] | list
"string"| str
number | int或float
bool | True或False
null | None

+ Python内置的`json`模块提供了非常完善的Python对象到JSON格式的转换
+ 把Python对象转为`json`对象，使用`json.dumps(d)`
+ 把JSON反序列化为Python对象，用`loads`或者对应的`load()`方法。

```python
import json
d = dict(name='mark', age=18)
print(json.dumps(d))
# {"name": "mark", "age": 18}

str = str(json.dumps(d))
print(json.loads(str))
# {'name': 'mark', 'age': 18}
```
#### 5.2 JSON进阶
+ `class`是不能直接被转为`json`格式的，因为`class`对象不是一个可序列化为`json`的对象
+ 使用`dumps()`方法第二个参数可以转换，第二个参数是转换方法
+ 下边这样转换会报错`TypeError: Object of type 'Student' is not JSON serializable`

```python
import json


class Student(object):
    def __init__(self, name, age, score):
        self.name = name
        self.age = age
        self.score = score


mark = Student('mark', 18, 99)
print(json.dumps(mark))
```
+ 写一个转换函数，用来转换`class`

```python
import json

class Student(object):
    def __init__(self, name, age, score):
        self.name = name
        self.age = age
        self.score = score

def student2dict(std):
    return {
        'name': std.name,
        'age': std.age,
        'score': std.score
    }

mark = Student('mark', 18, 99)
print(json.dumps(mark, default=student2dict))
```
+ 但是如果下次再遇到一个`Animal`类，还是无法转换，所以把`class`示例变为`dict`，因为通常`class`的实例都有一个`__dict__`属性，他就是`dict`，用来存储实例变量。少数例外，比如定义了`__slots__`的`class`

```python
import json

class Student(object):
    def __init__(self, name, age, score):
        self.name = name
        self.age = age
        self.score = score


mark = Student('mark', 18, 99)
print(json.dumps(mark, default=lambda x: x.__dict__))
```
+ 如果要把JSON反序列化为一个`Student`对象实例，`loads()`方法首先转换出一个`dict`对象，然后传入的`object_hook`函数负责把`dict`转换为`Student`实例

```python
import json

class Student(object):
    def __init__(self, name, age, score):
        self.name = name
        self.age = age
        self.score = score

def dict2class(d):
    return Student(d['name'], d['age'], d['score'])

str = '{"name": "mark", "age": 18, "score": 99}'

print(json.loads(str, object_hook=dict2class))

# <__main__.Student object at 0x000002034790A668>
```
+ `json`模块的`dumps()`和`loads()`函数时定义的接口典范，使用的时候，只需要传入一个必须的参数。
+ 当默认的序列化或反序列化机制不满足我们的要求时，可以传入更多的参数来定制序列化或反序列化的规则，即可以简单使用接口，又可以充分的灵活扩展
